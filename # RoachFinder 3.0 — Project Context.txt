## What This Project Is

**RoachFinder** is a personal NFL spread prediction web application. Each week during the NFL regular season (Weeks 2–16 only — Week 1 and Week 17 are intentionally excluded), the pipeline:

1. Scrapes NFL game data for the upcoming week
2. Runs a Python prediction algorithm that scores each matchup with a **Confidence Factor**
3. Displays the results on a public static website at **https://www.roachfinder.com/**

The project is rebuilt from scratch each season. This is version **3.0**, targeting the **2026–2027 NFL season**.

## Algorithm — Core Concepts (DO NOT MODIFY)

These must be preserved **exactly** as implemented in the original Python predictor. Do not alter the math.

### Confidence Factor
- A numeric score computed per matchup
- Higher = more confident the algorithm's pick will cover the spread
- Formula lives in the original predictor Python file — copy it verbatim

### Rolling Median Confidence Factor
- The **median** of all Confidence Factor values across all picks in the current season to date (not just current week)
- Updates each week as new picks are added
- Used as the threshold for "Above Median" picks

### Pick Categories
| Category | Definition |
|---|---|
| All Spreads | Every pick the algorithm makes (Weeks 2-16) |
| Above Median | Picks with CF >= Rolling Median CF |
| Top 5 | The 5 picks with the highest CF each week |

### Season Scope
- **Active weeks:** 2 through 16
- **Excluded:** Week 1 and Week 17 (by design — do not change this)
- Season label format: `YYYY-YY` (e.g., "2026-27") for short form, `YYYY-YYYY` for long form

## Data Per Game (what the scraper must collect)

Each game record needs the following fields:

**From scraper:**
- `away_team` — team name (string)
- `home_team` — team name (string)
- `stadium` — full stadium name + city, state
- `game_time` — date + time string (e.g., "Sunday 1:00 PM ET")
- `cheapest_ticket` — dollar amount (integer)
- `over_under` — float (e.g., 50.5)
- `spread_line` — float (e.g., -13.5 from the favored team's perspective)
- `favored_team` — team name of the favored team

**From predictor (added after algorithm runs):**
- `pick_winner` — team the algorithm predicts will cover
- `pick_loser` — the other team
- `confidence_factor` — float, 2+ decimal places
- `winning_pick_label` — formatted string, e.g., "Patriots -13.5" or "Chiefs +13.5"

## Season Record Tracking

The app must track and persist results week-over-week in `data/season_record.json`.

For each completed week, record:
- Which pick was made (team + line)
- Result: `win`, `loss`, or `push`
- Category flags: was it Above Median? Was it a Top 5 pick?

Cumulative records (W/L/%) for All Spreads, Above Median, and Top 5 are calculated from this data and displayed on Home and History pages.

Results are entered **manually** after each week's games complete (the algorithm does not auto-update results). The rebuild should include a simple way to enter results — either a CLI script (`enter_results.py`) or a clearly documented process for editing the JSON directly.

## Streamlining Goals (Original -> 3.0)

The original project used CSV files and had multiple manual steps. The 3.0 rebuild should:

| Problem in original | Fix in 3.0 |
|---|---|
| CSV files as intermediate data format | JSON throughout — one format, one `/data/` folder |
| Multiple scripts run in unclear order | Single `run_week.py` entry point: scrape -> predict -> write JSON |
| Manual copy-paste of data into HTML | JS reads `/data/current_week.json` at page load |
| Season rollover requires touching many files | Single `config.py` with season year, week range, and constants |
| Redundant/leftover scripts | Clean slate — only files that serve a purpose |

### Target Directory Structure

```
F:\CodeProjects\RoachFinder_3.0_2026_ClaudeBuild\
|-- config.py                  # Season year, week range, affiliate link, etc.
|-- scraper.py                 # Fetches raw weekly game data -> data/raw_week_XX.json
|-- predictor.py               # Runs algorithm -> data/current_week.json
|-- run_week.py                # Entry point: runs scraper then predictor
|-- enter_results.py           # CLI tool to record W/L/push for completed weeks
|
|-- data/
|   |-- current_week.json      # This week's picks + game info (generated by predictor)
|   |-- season_record.json     # All weeks' results + cumulative W/L by category
|   `-- history.json           # Prior seasons' records (manually maintained per season)
|
`-- site/
    |-- index.html
    |-- current-week.html
    |-- history.html
    |-- about.html
    |-- calculator.html
    |-- style.css
    |-- main.js                # Shared JS utilities
    |-- current-week.js        # Fetches + renders current_week.json
    |-- history.js             # Fetches + renders season_record.json + history.json
    `-- data/                  # Copy of root /data/ — uploaded to server each week
```

### Deployment Workflow (each week)
1. Run `python run_week.py` locally — generates `data/current_week.json`
2. After games complete, run `python enter_results.py` — updates `data/season_record.json`
3. Copy updated `/data/` files into `site/data/`
4. Upload the `site/` folder to cPanel via File Manager or FTP
5. Done — no server-side build step, no database, no Node.js
